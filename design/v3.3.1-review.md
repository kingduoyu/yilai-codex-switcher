# v3.3.1 原生界面设计记录

使用 Product Design index、user-context、get-context 和现有界面审阅流程；无已保存的设计上下文。目标是已有 Windows / macOS 工具，面向不了解 Codex 配置细节的用户。

旧界面问题：主页面同时展示生图、配置、同步、撤销、清理，用户必须先理解工具内部能力；正文和按钮权重接近，窗口偏大。Windows 字体与控件布局缺少统一。

设计目标：一张连接卡片。品牌标题与当前连接分开；Key 输入与两个主动作形成顺序；蓝色突出 API，官方使用白色边框；自动生图/历史同步仅用一句说明。重置在右下角弱化，不出现确认弹窗。Key 显隐仅为输入辅助。

颜色：背景 #F5F7FB、文字 #182338、次级文字 #6F7B90、主操作 #2563EB、边框 #E1E7F0。Windows 740×520，macOS 760×520；使用各平台原生渲染和控件。保留键盘焦点、密码遮罩、忙碌禁用和关闭保护；错误留在状态区。

验收流程：
1. 初始页：两主要按钮可一眼辨认；Key 标签与官方无需 Key 的说明完整。
2. API 入口：空 Key 不写文件；填写后配置、登录处理、历史同步作为一次操作，只有完成才显示成功。
3. 官方入口：不要求 Key；恢复原生认证，自动同步，提示重开登录。
4. 重置入口：直接改名 config.toml，不弹确认，不碰 auth/历史。
5. 失败状态：保持界面可用并显示具体原因，文件操作失败按测试还原。

Windows 最终截图：dist/windows-v331.png。macOS 截图由对应 Actions 制品提供。截图检查只证明布局；认证、同步、回滚另外使用原生自测及真实 app-server 集成验证。
